# 05: Local Postgres and the example service's first migration

Part of [the spec](../spec.md); delivers user stories 14 (Postgres), 15 and 16.

## What to build

A contributor can run the example service against a local database:

- **Infrastructure:** `vp run infra:up` starts Postgres in Docker Compose and waits until it is healthy. `vp run infra:down` stops it.
- **Databases:** on a fresh volume, Postgres creates a role, a database and a shadow database for each service with a database. So far that is only the example service.
- **Migrations:** the example service's `dev` script brings its database up to date with the committed migrations before it starts. `db:watch` re-applies `current.sql` on every save. `db:reset` rebuilds the development database from the committed migrations.
- **Schema dump:** running migrations regenerates the committed `schema.sql`.

The first committed migration creates the example service's messages table, following the naming rules in the database migrations pattern. It is written through the pattern's own workflow, so that workflow is exercised once for real.

## Acceptance criteria

- [ ] `vp run infra:up` on a clean machine starts Postgres and returns once it is healthy. `vp run infra:down` stops it.
- [ ] Compose's Postgres image is pinned by tag and digest, at the current Postgres major (checked when the ticket is planned).
- [ ] On a fresh volume, the example service's role, database and shadow database exist, and the service connects as its own role.
- [ ] `vp run --filter <example> dev` migrates, then starts the service. A second run finds nothing to migrate.
- [ ] `db:watch` re-applies `current.sql` on save, and `db:reset` rebuilds the database from the committed migrations.
- [ ] The committed migration creates the messages table with snake_case names, a plural table name, an `id uuid` primary key with no default, and `created_at` defaulting to `now()`.
- [ ] `schema.sql` is regenerated by running migrations, through `pg_dump` inside the container, and is committed.
- [ ] `current.sql` holds only comments at the end of the ticket.
- [ ] The local development guide's status note is updated for what now runs.
- [ ] The database migrations pattern's exemplar names the example service's first migration and `.gmrc`.
