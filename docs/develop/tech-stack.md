# Tech stack

The technologies used in this repository, each linked to its own docs, with the ADR that explains the choice. Everything here is TypeScript; games and players in other languages live in their own repositories and connect through the protocols. Versions are pinned in `package.json` and `.nvmrc`, not here.

| Area                 | Technology                                                                                                                                                                                                                                                                           | ADR                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Language and runtime | [TypeScript](https://www.typescriptlang.org/docs/) on [Node](https://nodejs.org/docs/latest/api/)                                                                                                                                                                                    | [0007](../adr/0007-write-the-repository-in-typescript-on-node.md)             |
| Running TypeScript   | Node's [type stripping](https://nodejs.org/api/typescript.html), ESM only, no build step                                                                                                                                                                                             | [0018](../adr/0018-run-typescript-source-directly.md)                         |
| Database             | [PostgreSQL](https://www.postgresql.org/docs/), one database per service                                                                                                                                                                                                             | [0008](../adr/0008-store-service-data-in-postgresql.md)                       |
| HTTP framework       | [Hono](https://hono.dev/docs/) for every service, wired by hand with no DI container                                                                                                                                                                                                 | [0009](../adr/0009-build-every-service-with-hono.md)                          |
| Validation           | [zod](https://zod.dev/) at every boundary                                                                                                                                                                                                                                            | [0010](../adr/0010-use-zod-as-the-only-schema-library.md)                     |
| Database access      | [Slonik](https://github.com/gajus/slonik), plain SQL with rows validated by zod                                                                                                                                                                                                      | [0011](../adr/0011-access-postgresql-with-slonik.md)                          |
| Background jobs      | [graphile-worker](https://worker.graphile.org/), queued in the same transaction as the data                                                                                                                                                                                          | [0012](../adr/0012-run-background-jobs-with-graphile-worker.md)               |
| Migrations           | [Graphile Migrate](https://github.com/graphile/migrate), plain SQL, forward-only                                                                                                                                                                                                     | [0013](../adr/0013-migrate-databases-with-graphile-migrate.md)                |
| Web frontend         | [React](https://react.dev/) single-page app on [Vite](https://vite.dev/), with [Mantine](https://mantine.dev/), [TanStack Router](https://tanstack.com/router/latest), [TanStack Query](https://tanstack.com/query/latest) and Hono's [RPC client](https://hono.dev/docs/guides/rpc) | [0014](../adr/0014-build-the-frontend-as-a-react-spa.md)                      |
| Translations         | [react-i18next](https://react.i18next.com/), English only for now                                                                                                                                                                                                                    | [0015](../adr/0015-set-up-translations-from-the-start.md)                     |
| Package manager      | [pnpm workspaces](https://pnpm.io/workspaces), a `package.json` per package                                                                                                                                                                                                          | [0016](../adr/0016-organise-the-repository-as-pnpm-workspaces.md)             |
| Dependencies         | pnpm's [supply-chain settings](https://pnpm.io/settings): one-week release age, no trust downgrades, reviewed build scripts; CI actions pinned by SHA                                                                                                                                | [0020](../adr/0020-guard-the-dependency-supply-chain.md)                      |
| Toolchain            | [Vite+](https://viteplus.dev/) (`vp`), with [Vitest](https://vitest.dev/), [Oxlint](https://oxc.rs/docs/guide/usage/linter) and [Oxfmt](https://oxc.rs/docs/guide/usage/formatter); no Nx                                                                                            | [0017](../adr/0017-build-test-lint-and-format-with-vite-plus.md)              |
| Local infrastructure | [Docker Compose](https://docs.docker.com/compose/) for Postgres; services run on the host                                                                                                                                                                                            | [0030](../adr/0030-run-infrastructure-in-compose-and-services-on-the-host.md) |
| Configuration        | [dotenv](https://github.com/motdotla/dotenv) loads each service's env files in its config module                                                                                                                                                                                     | [0031](../adr/0031-load-configuration-only-in-each-services-config-module.md) |
| CI                   | [GitHub Actions](https://docs.github.com/en/actions): pull-request and main workflows calling a reusable quality-check workflow                                                                                                                                                      | [0019](../adr/0019-compose-ci-from-reusable-workflows.md)                     |
| Commit messages      | [commitlint](https://commitlint.js.org/) checks pull request titles as [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/)                                                                                                                                        | [0026](../adr/0026-write-pull-request-titles-as-conventional-commits.md)      |

Observability and authentication are not decided yet.

How the code is laid out and how a service is structured are in [Codebase](./codebase.md).
